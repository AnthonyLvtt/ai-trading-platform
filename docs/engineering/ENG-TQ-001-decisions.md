## Authority

Qualification is not authorization. Shadow is a qualification mode, not a new OPS
environment. The only accepted source is an actual validated Risk(TEST) APPROVED
decision. Its Strategy, symbol, side, market context and upstream identities are
checked by the Exchange owner before projection. It never becomes Risk(TESTNET).

`ShadowIntent` explicitly carries source TEST, target TESTNET and
`submission_authorized=false`. Its projection is a distinct type, not an executable
ExchangeOrderRequest or TestnetExecutionAuthorization. No TQ entry point accepts a
transport. Neither credentials nor signing are involved. No order, cancellation or
Exchange fill is generated by Shadow. Result `side_effect_performed=false` is fixed.
Risk, OPS and Release policies are unchanged, including TESTNET and LIVE blocks.

## External quantity and filters

Quantity is the positive finite Decimal fact in the existing UpstreamOrderProof.
It is never calculated, defaulted or adjusted. Missing proof blocks with
SIZING_EVIDENCE_REQUIRED; non-approved Risk yields no intent.

A complete injected symbol record supplies symbol status, order types and the
explicit filter list. TRADING and MARKET are mandatory. Unknown filter types block
with UNSUPPORTED_SYMBOL_FILTER; duplicates/missing/malformed rules also block.
PRICE_FILTER is parsed but not applied to the price-less MARKET projection.
MARKET_LOT_SIZE takes priority over LOT_SIZE. Nonzero quantity bounds and step are
checked exactly; zero bounds/step disable that individual test. Fraction arithmetic
on Decimal inputs avoids ambient Decimal precision rounding or truncation.

NOTIONAL takes priority over MIN_NOTIONAL. Only MARKET-applicable bounds are used.
An absent notional filter is acceptable only via the explicit complete symbol filter
list. Applicable notional requires a positive price with matching symbol, source
identity, window and causal effective/observed times. A positive window requires
EXCHANGE_AVERAGE_PRICE; zero requires EXCHANGE_LAST_PRICE. DATA_MARK is never enough
for concrete Shadow acceptance. No age threshold, price fallback or arbitrary close
is invented. Offline fixtures are explicit Exchange evidence, not claims of real
connectivity or currently tradable Binance symbols.

## Read-only reconciliation and parsing

Exchange owns public order/fill lookup projections and parsers in `exchange.read_only`.
`reconciliation_order_query` supports exactly one client ID or exchange ID;
`reconciliation_fills_query` requires the established exchange order ID. They describe
GET order / account-trades requests only and contain no credentials or signature.
They do not execute HTTP. New network connectivity and transport wiring are deferred.

Order status parsing includes NEW, PARTIALLY_FILLED, FILLED, CANCELED, PENDING_CANCEL,
REJECTED, EXPIRED and EXPIRED_IN_MATCH. Unknown strings remain UNKNOWN, produce a
blocked inspection and never imply safe retry. Fill records preserve provided Decimal
price/quantity/optional quote quantity and effective time. Duplicates, mismatched
order/symbol, future execution times and quantities exceeding reported execution
are rejected. The provided trades may be a partial history: no completeness,
Accounting state or portfolio reconciliation is inferred.

The existing submission reply mapper is exposed through a public parsing-only facade.
The internal mapper is now static, without changing its existing semantics. Tests
exercise authentication/authorization rejection, rate-limit rejection, timestamp
rejection, timeout before/after possible send, malformed response and ambiguity.
No new retry policy or clock-skew correction is introduced. UNKNOWN remains distinct
from rejection and cannot authorize retry. No background reconciliation loop exists.

## Ten qualification cases and evidence

`ATP_TESTNET_QUALIFICATION_V1 / 1.0` is locked and revalidated. The closed catalogue is
TQ-ADAPTER, SERIALIZE, PARSE, IDEMPOTENCY, FILTERS, FAILCLOSED, RECONCILE, SHADOW,
SECURITY and BOUNDARY (each suffixed -001). Each case has an explicit mapping to
assertion-based probes; a global pytest exit code is not sufficient evidence.

The collector records per-probe setup/call/teardown results and referenced domain
content identities. Static checks refer to the exact source inventory. It binds all
contracts to the Git commit and complete tracked repository identity, checked before
and after collection. Typed/stored identity checks, expected probe coverage, duplicate
detection, policy and source compatibility precede case evaluation.

Missing/invalid evidence is BLOCKED, an executed failed invariant is FAILED, and
sufficient successful evidence is PASSED. Suite priority is BLOCKED > FAILED > PASSED.
Input contract ordering does not change the result. Consumers can use
`inspect_qualification` to revalidate a result against their own exact commit/tree.

Evidence is local and reproducible, not a signed third-party attestation. An arbitrary
caller can construct self-consistent claims; the canonical collector is responsible
for establishing observations by executing the actual probes. Offline PASSED means
these contracts passed, not that a real account, symbol or exchange is authorized.

## Collector, observability and security

```bash
UV_CACHE_DIR=/tmp/atp-uv-cache uv run python scripts/qualify_testnet.py \
  --output /tmp/testnet-qualification.json
```

The canonical JSON includes the result, case results, source and adapter/policy
identities, explicit contract/probe evidence and `side_effects_performed=false`.
No wall-clock timestamp participates in the identity. The vertical contract records
real DATA/Strategy/Risk/Shadow and existing Observability event identities.
The closed EventType taxonomy is unchanged; no fabricated Exchange event is emitted.

The main TQ suite disables sockets, adapter submit/reconcile and HTTP perform using
failure guards. No normal test or collector requires internet or credentials. Sensitive
keys use the existing Observability policy; rejected values are not echoed. Malformed
runtime inputs and pre/post-composition identity tampering fail closed.

Optional read-only connectivity evidence is not implemented or required for offline
PASS. There is no real Testnet request, signed GET, order smoke test, credential loading,
withdrawal, sizing, OPS activation, release promotion or Live route in this parcours.
Future activation requires a separate CTO mission aligning Risk + OPS + Exchange +
Release, with actual connectivity/account/filter and operational evidence.
